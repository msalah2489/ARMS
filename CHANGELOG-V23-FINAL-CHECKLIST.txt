ARMS V2.2.1 – Final checklist correction pass

This pass is based on the user's red/yellow/new checklist after V2.2 testing.

FIXED / REVIEWED:
1. Column sorting: all tables now support click on any header -> ascending -> descending, with visible arrows and cache-busted JS.
2. Service Requests filter: added "جاهز للإرسال" and made status filtering location-based; search includes request number, device code, serial, customer and phone.
3. Branch request status: hides internal maintenance states from the branch-facing request list and shows lifecycle states such as جديد، في الطريق للصيانة، قيد الصيانة، جاهز للإرسال، مغلق، ملغى، معلق.
4. Sent request status: a request whose non-excluded devices have all been sent is shown as مغلق, while branch receiving still tracks the physical device location separately.
5. Reports: model filter is now a clear list of actual models for the user's branch; request reports filter by model through their devices; device reports expose request number, customer, branch, model, serial, problem, current location, operational status, decision, lifecycle status, priority and dates.
6. Ready-to-send filter: only devices physically in "مستودع الأجهزة الجاهزة للإرجاع" with status "جاهز للإرسال" are included.
7. Technician completion: repair cause/action are visibly mandatory only when actual maintenance was started; consumed parts are optional and default to "لم يتم استخدام قطع غيار" when empty.
8. Technician completion location: remains "مستودع الأجهزة الجاهزة للإرجاع" after completion.
9. Multi-device request: completing one device no longer marks the entire request ready if another non-terminal device is still in process.
10. Technician availability: a technician with an active device does not see other waiting devices in his own workspace; those unassigned devices remain available to other technicians.
11. Urgent devices: "عاجل" is red and blinking in the technician workspace.
12. Supervisor receiving: added "تحديد الكل" and "إلغاء التحديد" while keeping individual selection.
13. Receiving success message: cleared when switching receiving tabs.
14. Supervisor dispatch of multi-device request: sending one selected device checks the other devices in the same request against actual readiness; if another device is not ready, the supervisor chooses to send only the selected device or defer it.
15. Replacement: external replacement devices are created inside ARMS with a new device code instead of requiring an existing inventory record. New/used condition remains mandatory. "من مستودع الصيانة" is optional and, when selected, shows available maintenance-warehouse replacement inventory.
16. Replacement barcode: replacement devices require QR/barcode printing before dispatch; the replacement remains visible in the ready-to-send list with a "طباعة QR أولاً" action until printed.
17. Branch naming: branch navigation now uses "إنشاء طلب" instead of the ambiguous "الاستلام" for the new-request page; the button remains "إنشاء طلب صيانة للعميل".
18. Edit request: before sending, branch users can edit model, customer complaint, external condition and accessories. Customer, phone, priority and request status remain locked.
19. Return-after-maintenance ambiguity: removed the old individual return action from the pre-dispatch preparation page; complete-request cancellation remains available before final dispatch from request details.
20. Startup state normalization: completed devices are normalized to the repaired-device warehouse, not the maintenance center, and devices already in transit to the branch or returning to maintenance are protected from being downgraded.
21. Dashboard ready count now uses the actual repaired-device warehouse/status instead of SentAt == null alone.
22. System version displayed as v2.2.1.

NOTE:
The development environment used for this packaging does not contain the .NET SDK, so a local dotnet build cannot be executed here. The source was statically reviewed and the previous working V2.2.0 structure was preserved. The first test step on Windows must remain `dotnet build`; any compiler error should be sent back before functional testing.
