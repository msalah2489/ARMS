# تفعيل إشعارات المتصفح (Web Push) — ARMS

الموقع على GitHub Pages ثابت (بدون سيرفر إرسال). لذلك:

- المتصفح يشترك ويحفظ الاشتراك في جدول Supabase.
- الإرسال يتم عبر **Supabase Edge Function** بمفتاح VAPID الخاص (سرّ).
- مفتاح VAPID العام فقط يظهر في بناء Pages.

## ماذا يصل كـ Push؟

أي إشعار يُنشأ داخل النظام عبر `notifications-store`، ومنه:

- رسائل المدير (صفحة الرسائل والإشعارات).
- تنبيهات نقص المخزون.
- تنبيهات النظام الأخرى (مثل تعليق صيانة يحتاج استبدال).

الإشعار داخل التطبيق (الجرس) يبقى كما هو؛ الـ Push إضافة له على الأجهزة المشتركة.

## مرة واحدة — خطوات M

### 1) تشغيل SQL

في Supabase → **SQL Editor** الصق وشغّل الملف:

`supabase/migrations/026_web_push_subscriptions_RUN_ME.sql`

ينشئ جدول `app_push_subscriptions`.

### 2) توليد مفاتيح VAPID

على جهازك (مرة واحدة):

```bash
npx web-push generate-vapid-keys
```

ستحصل على **Public Key** و **Private Key**.

### 3) أسرار Edge Function (المفتاح الخاص هنا فقط)

في Supabase → **Project Settings → Edge Functions → Secrets** (أو CLI):

| السر | القيمة |
| --- | --- |
| `VAPID_PUBLIC_KEY` | المفتاح العام |
| `VAPID_PRIVATE_KEY` | المفتاح الخاص |
| `VAPID_SUBJECT` | مثلاً `mailto:you@example.com` |

**مهم:** نفس المفتاح العام يجب أن يُستخدم في بناء Pages (`NEXT_PUBLIC_VAPID_PUBLIC_KEY`). إذا اختلف الزوج، الـ Push يفشل بصمت من خدمة المتصفح.

ثم انشر الدالة من مجلد المشروع:

```bash
npx supabase login
npx supabase link --project-ref YOUR_PROJECT_REF
npx supabase functions deploy send-web-push
```

مصدر الدالة: `supabase/functions/send-web-push/index.ts`

بعد أي تعديل على الدالة: أعد `deploy` ثم راجع **Edge Functions → send-web-push → Logs**.

### 4) المفتاح العام في بناء GitHub Pages

أضف **المفتاح العام فقط** كـ Actions Secret أو Variable:

- الاسم: `NEXT_PUBLIC_VAPID_PUBLIC_KEY`
- القيمة: نفس Public Key

أو ضعه في `.env.production` / `.env.local` محلياً:

```env
NEXT_PUBLIC_VAPID_PUBLIC_KEY=BNxxxxxxxx...
```

**لا تضع** `VAPID_PRIVATE_KEY` في GitHub أو في ملفات Next.

بعد الدفع إلى `main` ينتظر اكتمال **Deploy GitHub Pages** ثم **Ctrl+F5**.

### 5) تفعيل الإشعار على جهاز الموظف (مرة لكل متصفح)

مهم: المتصفح **لا** يطلب الإذن تلقائياً بعد تسجيل الدخول. يظهر بانر عربي أسفل الشاشة، والإذن الرسمي يظهر فقط بعد الضغط على **تفعيل الإشعارات**.

1. سجّل الدخول إلى ARMS.
2. تظهر رسالة أسفل الشاشة: **تفعيل إشعارات المتصفح** → اضغط **تفعيل الإشعارات**.
3. وافق على إذن المتصفح.
4. أو من قائمة الجرس: **تفعيل إشعارات هذا الجهاز**.

بعدها يصل الـ Push حتى لو كانت النافذة في الخلفية (حسب دعم المتصفح).

إذا ظهر بانر **إشعارات المتصفح غير جاهزة** بدل زر التفعيل: المفتاح العام ناقص من بناء Pages — راجع الخطوة 4 وأعد النشر.

## تحقق سريع (بعد التفعيل)

1. في سجل Deploy GitHub Pages يجب أن تظهر جملة طول مفتاح VAPID (وليس تحذير أنه فارغ).
2. بعد التفعيل: Supabase → **Table Editor** → `app_push_subscriptions` → صف فيه `user_id` الخاص بك و`endpoint` طويل.
3. أرسل رسالة تجريبية من المدير لدورك/حسابك (الجهاز المستقبل يجب أن يكون قد فعّل الإشعارات).
4. في Supabase → **Edge Functions** → `send-web-push` → **Logs**: طلب ناجح و`sent` أكبر من 0.
5. يظهر إشعار نظام التشغيل + رسالة في الجرس داخل الموقع.

إذا ظهر في السجل `skipped: no subscriptions`: لم يُحفظ صف الاشتراك — أعد التفعيل من الجرس وتأكد من الخطوة 2 (SQL).

إذا ظهر خطأ VAPID في السجل: راجع تطابق المفتاح العام/الخاص (الخطوتان 3 و 4).

### إعادة تعيين إذن مرفوض (Chrome على الكمبيوتر)

1. افتح الموقع → أيقونة القفل بجانب العنوان.
2. **إعدادات الموقع** → **الإشعارات** → اختر **السماح** (أو امسح الإعداد وأعد تحميل الصفحة).
3. اضغط الجرس → **تفعيل إشعارات هذا الجهاز**.

## الجوال: Chrome Android مقابل Safari iOS

### Chrome على Android

- يدعم Web Push من تبويب عادي على **HTTPS** (GitHub Pages مناسب).
- بعد **تفعيل الإشعارات** وموافقة المتصفح، يصل إشعار النظام حتى والتطبيق في الخلفية.
- تأكد أن إعدادات Android لا تمنع إشعارات Chrome لهذا الموقع.

### Safari على iPhone / iPad (حدّ مهم)

- Web Push على iOS **غير متاح من تبويب Safari العادي**.
- المطلوب تقريباً:
  1. **iOS 16.4** أو أحدث.
  2. فتح الموقع في Safari.
  3. **مشاركة → إضافة إلى الشاشة الرئيسية** (Add to Home Screen).
  4. فتح ARMS من أيقونة الشاشة الرئيسية (وضع تطبيق ويب / standalone).
  5. تسجيل الدخول ثم **تفعيل الإشعارات** من داخل التطبيق المضاف.
- بدون الإضافة للشاشة الرئيسية: الجرس داخل الموقع قد يعمل، لكن **إشعار نظام iOS لن يصل**.
- Chrome/Firefox على iOS يستخدمان محرك WebKit؛ نفس قيود Safari تنطبق عموماً.

## ملاحظات سريعة

- يحتاج HTTPS (GitHub Pages يدعمه). Service Worker يعمل تحت المسار `/ARMS` على Pages.
- بدون `NEXT_PUBLIC_VAPID_PUBLIC_KEY` في البناء: يظهر تنبيه إعداد بدل إخفاء الواجهة بصمت.
- بدون نشر Edge Function أو بدون أسرار VAPID الخاصة على Supabase: الإشعارات داخل التطبيق تعمل، والـ Push لن يُرسل.
- عند تدوير مفاتيح VAPID: حدّث Secrets + GitHub ثم أعد النشر، وعلى كل جهاز اضغط **تفعيل إشعارات هذا الجهاز** من جديد.
